01

Контекст и задачаContext and task

До старта проекта у EAJ Trader уже были айдентика и лендинг, но не было личного кабинета. Пользователь мог познакомиться с продуктом, но не мог перейти к основным операциям: открыть и настроить торговый счёт, пополнить или вывести средства, выполнить перевод и проверить баланс.Before the project started, EAJ Trader already had an identity and a landing page, but no personal dashboard. A user could learn about the product, but couldn't move on to the core operations: open and set up a trading account, deposit or withdraw funds, make a transfer, or check the balance.

Бизнесу требовалось за два месяца запустить рабочий MVP и превратить лендинг из витрины в полноценную точку входа в продукт.The business needed a working MVP shipped in two months, turning the landing page from a showcase into a full entry point into the product.

Моя задача состояла в том, чтобы определить приоритетные сценарии первой версии, спроектировать структуру личного кабинета и заложить основу для дальнейшего развития продукта.My task was to identify the priority scenarios for the first version, design the dashboard's structure, and lay the foundation for the product's further development.

02

ИсследованиеResearch

Заказчик уже определил список функций для первой версии. Чтобы расставить приоритеты, я сопоставила типы трейдеров, их цели, поведение и требования к интерфейсу.The client had already defined the feature list for the first version. To prioritize, I mapped trader types against their goals, behavior, and interface requirements.

Анализ показал, что один интерфейс не сможет одинаково хорошо отвечать потребностям всех сегментов. Для MVP требовалось выбрать основной сценарий и не перегружать первую версию функциями для всех типов пользователей.The analysis showed that a single interface couldn't equally serve every segment's needs. The MVP needed to pick one core scenario and avoid overloading the first version with features for every user type.

03

Фокус первой версииFirst-version focus

Анализ помог выделить пять типов пользователей. Для первой версии я сфокусировалась на активном трейдере, поскольку его сценарии формировали основу личного кабинета: управление счетами, пополнение, вывод, переводы и контроль баланса.The analysis helped identify five user types. For the first version I focused on the active trader, since their scenarios formed the foundation of the dashboard: managing accounts, deposits, withdrawals, transfers, and balance tracking.

«Скальпер», «Свинг-трейдер», «Инвест-трейдер» и «Новичок» в MVP не резолвились: в кабинете нет отдельного экрана исполнения сделок, ленты цен или риск-панели. Это зафиксированные направления для следующих итераций, а не забытая часть анализа."Scalper," "Swing trader," "Investor-trader," and "Beginner" weren't resolved in the MVP: the dashboard has no dedicated trade-execution screen, price feed, or risk panel. These are logged directions for future iterations, not a forgotten part of the analysis.

04

Работа над продуктомProduct work

Ключевые сценарии: управление счетами, пополнение, вывод средств, переводы между счетами и отслеживание состояния средств. Основной экран спроектирован вокруг быстрого доступа к операциям, вторичные и аналитические данные вынесены в менее приоритетные зоны, так пользователь быстрее находит состояние своих счетов и меньше сомневается, сколько средств доступно прямо сейчас.Key scenarios: managing accounts, deposits, withdrawals, transfers between accounts, and tracking fund status. The main screen is designed around quick access to operations, with secondary and analytical data moved to lower-priority zones, so the user finds their account status faster and is less uncertain about how much is available right now.

05

Работа с торговыми счетамиWorking with trading accounts

Торговый счёт стал центральной сущностью личного кабинета. Через него пользователь контролирует капитал, выполняет финансовые операции и отслеживает состояние активов.The trading account became the personal dashboard's central entity. Through it, the user controls their capital, performs financial operations, and tracks the state of their assets.

На этапе прототипирования я сравнила привычный табличный список и карточное представление. Оба варианта проверили в небольшом качественном UX-исследовании на базовых сценариях: найти счёт, определить его статус, пополнить или вывести средства.At the prototyping stage, I compared a familiar tabular list with a card-based view. Both were tested in a small qualitative UX study on basic scenarios: finding an account, determining its status, and depositing or withdrawing funds.

Табличный вариант был привычнее, но карточки помогали быстрее понимать состояние счёта и находить доступные действия. Поэтому карточный формат стал основным для первой версии, а таблицу сохранили как возможный сценарий для пользователей с большим количеством счетов.The table version was more familiar, but cards helped users understand an account's status and find available actions faster. So the card format became the primary choice for the first version, while the table was kept as a possible scenario for users with a large number of accounts.

06

Центр управления средствамиFunds management center

Объединила пополнение, вывод и внутренние переводы в единый раздел Funding. Решение приняли совместно с заказчиком, чтобы упростить навигацию и сократить количество разрозненных точек входа в финансовые операции. По результатам юзабилити-тестирования пользователи отмечали более простое восприятие структуры и быстрый доступ к операциям.I combined deposits, withdrawals, and internal transfers into a single Funding section. The decision was made together with the client to simplify navigation and reduce the number of scattered entry points into financial operations. Usability testing showed users found the structure easier to grasp and operations quicker to access.

07

Поддержка внутри продуктаIn-product support

Я добавила Claims & Complaints, встроенный раздел для обращений в формате чата. Пользователь может связаться с поддержкой внутри личного кабинета, не переходя во внешние каналы. На этапе запуска чат также помогает собирать обратную связь и находить точки для дальнейшего развития продукта.I added a Claims & Complaints section: a built-in requests block in chat format. In disputed situations, a fast, direct communication channel without hunting for outside contacts is critical. Early launch is expected to bring a higher volume of requests, so the chat became not just a support channel but also a feedback tool for improving the product.

08

РезультатResult

Спроектирован MVP веб-кабинета для управления финансовыми операциями. Заложенная структура решения позволяет масштабировать продукт за счёт добавления новых сценариев без нарушения основной логики взаимодействия.An MVP of the web dashboard for managing financial operations was designed. The solution's underlying structure allows the product to scale by adding new scenarios without breaking the core interaction logic.

Определены пять типов пользователей личного кабинета и их поведенческие модели, что позволило сфокусировать MVP на сценариях активных трейдеров.Five types of dashboard users and their behavioral patterns were identified, which allowed the MVP to focus on active traders' scenarios.

03

Архитектура кабинетаDashboard architecture

Сформирована структура кабинета, ориентированная на быстрые и частые финансовые операции: счета, пополнение, вывод, переводы.The dashboard structure was shaped around fast, frequent financial operations: accounts, deposits, withdrawals, transfers.
