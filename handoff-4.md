### Round 2 → Round 3 — homepage scroll mechanic, rebuilt twice
Round 2 built a per-project `position:sticky` chapter system. The user then asked for something closer to a true Floema-style stacked-panel cover-reveal, so **Round 3 replaced it entirely** with the architecture that's live now:

- `.projects-stage-wrap` (single wrapper, `height: 700svh` when active) → `.projects-stage` (`position: sticky; top:0; height:100svh` when active) → four `.project-showcase--*` siblings, each `position:absolute;inset:0` with `transform: translateY(var(--ty))` and z-index 1→4 (Alif→EAJ→Namaste→Tracker).
- One `requestAnimationFrame` loop (near the end of `index.html`'s `<script>`) computes scroll progress via `getBoundingClientRect()` only (never reads/writes `scrollTop`, never calls `preventDefault`) and writes `--ty`/`--scale`/`--media-o`/`--header-o`/`--desc-o`/`--cta-o` as inline custom properties on each scene, following the exact phase bands the user specified (0–10% below fold / 10–70% physical rise / 35–60% media fade / 50–72% header / 60–82% desc / 70–90% CTA / 90–100% held).
- `.js-stage-active` is added to the wrapper only if `!matchMedia('(prefers-reduced-motion:reduce)').matches` — **not** gated by viewport width, so mobile keeps the same rise-and-cover mechanic (confirmed: this was an explicit requirement, not an oversight).
- Mobile (`≤760px`) uses a *different internal layout* inside the same absolutely-positioned scene: image occupies the top ~56%, text sits on a solid `var(--surface)` strip below (not overlaid on the photo) — found live, this was necessary because `object-fit:cover` on these landscape photos leaves almost no side margin in a narrow portrait box, so full-bleed overlay text was reading straight across the subject.
- DESIGN.md was updated with the sections the user asked for: **Project Cover Composition** (§13.9), **Content Safe Zones** (§13.4), **CTA Spacing** (§13.5), **Stacked Project Transitions** (§13.8), **Scroll Progress and Layering** (§13.9a), **Responsive Project Scenes** (under §20), **Reduced Motion** (§21, updated).

### This session's fourth round of fixes (most recent, all live-verified)

1. **Namaste CTA button turning white/unreadable on hover** — real bug, found via direct CSSOM inspection, not guesswork: `.project-showcase--namaste:hover .project-showcase__cta` (dark override) and the generic `.project-showcase:hover .project-showcase__cta` (`background:#fff`) had **identical specificity** (0,3,0), and the generic rule sat later in the file, so it won the tie and silently turned the button white on hover. Fixed by adding a `.projects-stage-wrap` prefix to the Namaste-specific hover/focus-visible/active rules, bumping them to (0,4,0) so they win outright. Also added a previously-missing `:active` state for all four projects' CTAs.

2. **Auto-layout restructure of the project cards** — the project number (`.project-showcase__index`) used to be `position:absolute` with a fixed `top` offset, independent of the title block's actual height. On some viewport heights the two collided (found live at 768px tablet width — visibly touching). Fixed by moving the number into normal flow: `.project-showcase__header` now wraps index+title-row+meta as one flex column (`gap:10px`), and `.project-showcase__body` is a flex column with `gap:24px` between header/description/CTA — replacing four separate hand-tuned margins with one auto-layout gap. This also directly satisfies the user's explicit ask for "24px gap to the button, everywhere, via auto-layout."

3. **Hero orbit hard-clipping at the boundary with the first project scene** — `.hero` and `.hero-surround` both had `overflow:hidden` at a fixed/computed height shorter than the outer orbit ring's actual extent (ring r5 spans ~77cqw of container width; the box is only 56.25cqw tall) — this produced a visible hard rectangular cut right where the light hero met the dark first scene. Fixed by changing both to `overflow: visible`. No z-index changes were needed — `.projects-stage-wrap` already paints over the bleeding orbit tail purely from DOM order (both `.hero` and `.projects-stage-wrap` are positioned elements with z-index `0`/`auto`, and later-in-DOM wins that tie). Verified live: the ring curve now flows continuously across the boundary and fades naturally under the dark scene, no hard seam, no horizontal overflow introduced at any breakpoint tested (1440px, 375px).

4. **Em dash (—) / en dash (–) removal, sitewide** — the user asked for every `—`/`–` in RU+EN user-visible text across all 6 HTML files to be rewritten naturally (period/comma/colon/parentheses/rephrase — never a mechanical hyphen swap), with date ranges converted to "с X по Y" / "X to Y" and role/tag separators converted to the site's existing `·` convention. Done via 6 parallel background agents (one per file). **Verified**: a `grep` across all 6 files, excluding `<style>`/`<script>`/HTML-comment blocks, returns zero matches. One inconsistency was caught and fixed afterward: `case-360-tracker.html`'s `<title>`/`<meta description>` were initially skipped by its agent (flagged as a judgment call) while the other 5 files' agents fixed theirs — manually aligned it to match (middle dot in title, period in description).

5. **Experience section → accordion** — the three job entries in `index.html`'s `.experience` section were previously just a date/company/role line each, no detail. Added full RU/EN responsibilities+results content (from the user's own text) inside native `<details>/<summary>` elements — expands on click/Enter/Space with zero custom JS, keyboard/ARIA semantics come free from the browser. Block-level bilingual toggling for the new paragraph/list content uses a **new, separate attribute** `data-lang-block="ru"/"en"` (not the sitewide `[data-lang]`, which forces `display:inline` — wrong for `<h4>`/`<ul>`) — driven by the same `html.lang-en` class `i18n.js` already sets, so no JS changes were needed.

6. **New EAJ Trader cover photo wired in** — the previous cover (`assets/eaj-trader-showcase.jpg`) is deleted; `assets/eaj-trader-cover.png` now holds the real new laptop photo (found, after some back-and-forth, at `~/Desktop/Портфолио/reference/Eaj trader new.png` — a location that has nothing to do with either of the two "diverged copies" above; it was just copied in, source left untouched). **Found and fixed live**: this photo's aspect ratio (1.5:1) is narrower than most real desktop windows (16:9/16:10 ≈ 1.6–1.78:1), so `object-fit:cover` was showing the photo edge-to-edge with **zero native crop** on typical desktop sizes — meaning the text column was overlapping the laptop screen, because there was no crop for `object-position` to shift. Fixed with a uniform (non-distorting) `transform: scale(calc(1.4 * var(--scale, 1)))` + `transform-origin: -30% 30%` scoped to `@media (min-width:761px)`, folding in the existing scroll-driven `--scale` custom property so the entrance zoom animation still works on top of the fixed crop (they'd otherwise clobber each other — same `transform` property, same element). Verified live at 1440×900, 1024×768, 768×1024 (tighter but no clear overlap — the one remaining edge case, a rare aspect ratio), and 375×812 mobile (image-top/text-below layout, unaffected by any of this since text never overlays the photo there).
